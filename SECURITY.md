# Политика безопасности и модель угроз (SECURITY)

## Архитектурные гарантии безопасности

1. **Изоляция секретов и защита от подмены (Confused Deputy):**
   - Токены Wildberries хранятся исключительно в зашифрованном виде (`MultiFernet`: AES-128-CBC + HMAC-SHA256).
   - Каждый шифротекст криптографически привязан к `telegram_id` владельца внутри аутентифицированного конверта (`{"v": 1, "sub": "<telegram_id>", "tok": "<token>"}`). Перенос зашифрованного токена между строками БД приводит к отказу расшифровки (`TokenDecryptionError`).
   - Поддерживается бесшовная ротация ключей через список ключей в `TOKEN_ENCRYPTION_KEY=NEW_KEY,OLD_KEY`.

2. **Безопасная передача токенов в Telegram:**
   - Команда `/connect` удаляет исходное сообщение до сохранения токена; при невозможности удаления токен отклоняется.
   - При ошибочной отправке `/connect <токен>` в групповой чат сообщение немедленно удаляется (при наличии прав), токен не сохраняется, а пользователю выводится требование отозвать скомпрометированный токен в кабинете WB.
   - Перехватываются отредактированные сообщения (`edited_message`) с `/connect`.

3. **Только чтение и защита от SSRF / DoS во внешнем HTTP-клиенте:**
   - `WildberriesClient` использует жёсткий белый список эндпоинтов чтения, `follow_redirects=False` (защита от утечки заголовка `Authorization` при редиректах) и `trust_env=False`.
   - Потоковое чтение ответа ограничено по размеру (`10 MiB`), пагинация ограничена по числу страниц (`200`), формат токена проверяется на печатный ASCII без управляющих символов (защита от CRLF-инъекций и `UnicodeEncodeError`).

4. **Защита от исчерпания ресурсов и кросс-тенантных сбоев:**
   - Парсер чисел `parse_bounded_decimal` блокирует экспоненциальную запись (`1e99999999`), предотвращая OOM при форматировании `Decimal`.
   - Введён скользящий rate limiter с ограниченной памятью (LRU) и опциональный белый список `ALLOWED_TELEGRAM_IDS`.
   - Фоновый цикл мониторинга изолирует ошибки и таймауты каждого продавца (`asyncio.wait_for` + барьер исключений).

5. **Защита хранилища, логов и контейнера:**
   - Файл SQLite и директория данных получают права `0600` / `0700` на POSIX-системах, соединения гарантированно закрываются, используются только статические параметризованные SQL-запросы.
   - `RedactingLogFilter` вырезает управляющие символы (`\r`, `\n`) и маскирует токены Telegram, JWT, Fernet и заголовки `Authorization`.
   - Multi-stage Docker-образ монтирует код только для чтения (`root:root`, `0555`) и исполняется от непривилегированного системного пользователя `10001:10001`.

## Ротация ключа шифрования

1. Сгенерируйте новый ключ:
   ```sh
   python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
   ```
2. Укажите новый ключ первым в `TOKEN_ENCRYPTION_KEY`:
   ```env
   TOKEN_ENCRYPTION_KEY=<НОВЫЙ_КЛЮЧ>,<СТАРЫЙ_КЛЮЧ>
   ```
3. Перезапустите приложение — новые подключения шифруются новым ключом, а существующие продолжают расшифровываться старым.
